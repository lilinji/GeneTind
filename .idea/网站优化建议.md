# GeneTind 网站改版建议

## 从“科技服务集合页”到“生命科学智能基础设施品牌”

**作者：Manus AI**  
**审阅范围：** GeneTind 首页、GneroAI 页面、HPC 页面，以及 taste-skill 的设计审计方法与公开站点。  
**结论：** GeneTind 当前的深色科技基调已经具备可信的企业感，但它仍更像一个叠加了 AI、HPC、硬件代理、课程与开源链接的模板型网站。下一步不应该简单加更多渐变、玻璃卡片或炫酷粒子，而应建立一个清晰、克制且可验证的 **AI + Gene** 视觉系统：让“组学数据如何被组织、推理与转化”为页面主角，让 AI 与基因组学在信息结构和视觉语言中真正发生连接。

> 建议将 GeneTind 定义为：**面向生命科学的智能数据与计算基础设施**。  
> 这比“AI 公司”“HPC 供应商”或“生信服务商”的单一标签更能容纳 GneroAI、组学 Workflow、私有化部署、HPC 和数据安全等现有能力。

---

## 1. 审阅结论与核心判断

当前网站的优势是已经拥有多组学分析、智能体、HPC、数据安全和工作流等可组成完整能力链的资产，并且在首页、GneroAI 与 HPC 页面中已初步使用深色背景、蓝紫高光及网格化组件。但这些页面大量复用相似的居中标题、等宽卡片、细描边、蓝紫渐变和抽象网格，导致不同产品在视觉上近似，品牌个性被通用 AI SaaS 风格稀释。首页同时放入技能库、OpenClaw 课程、硬件品牌、客户评价、订阅方案与生态动画，信息广度大于叙事聚焦度。[1]

GneroAI 页将 Chat、Agent、Skills 平铺为三张同构卡片，用户无法快速理解它们如何服务一个真实的研究任务。HPC 页拥有较丰富的技术信息，但“产品矩阵”和规格卡片出现过早、过密，且与 GneroAI 使用几乎同一套背景与组件语言，弱化了“软件智能层”和“计算基础设施层”本应具备的区分。[2] 参考 taste-skill 的价值不在于复制其视觉，而在于采用其“先审计、再重构”的方法：先解决产品主张、版式差异、信息密度和内容真实性，再考虑动效、发光或表面装饰。[3] [4]

| 现有症状                                                 | 对用户的影响                                      | 建议的重构方向                                                                         |
| -------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 一个首页承担平台、硬件、课程、社区、开源和订阅等多种目标 | 科研客户、企业 IT、采购方和开发者无法判断首要行动 | 以“研究数据到可解释洞见”的主叙事组织首页，其余业务放入明确的产品与资源层级             |
| 深蓝黑、紫色光晕、网格和圆角卡片被频繁复用               | 有技术感，但缺乏生命科学的独特辨识                | 用“真实数据组织方式”替换通用装饰，如样本谱系、组学层、序列片段、工作流图与可信计算边界 |
| GneroAI、HPC、Skills 的角色并列且名称体系分散            | 产品架构不易理解，销售与内容团队难以形成一致话术  | 建立母品牌、平台、基础设施和扩展能力的四层命名体系                                     |
| CTA 有“获取 Pro”“GitHub Star”等模板化导向                | 与企业科研和项目制采购的高意图路径不吻合          | 首要 CTA 改为“预约方案评估”或“查看研究工作流”，次要 CTA 才是文档、GitHub 和社区        |
| 大量性能、兼容、客户与合作描述集中出现                   | 一旦无法验证，反而降低生命科学领域最看重的可信度  | 仅保留已验证数据；对路线图能力明确标为“开发中”或“即将开放”                             |

## 2. 先定品牌，不先定特效

### 2.1 品牌叙事

建议将原本较宽泛的“生命科学 IT 数据分析综合解决方案”收束为一句能形成画面感的价值主张：

> **让组学数据成为可推理、可复现、可行动的研究能力。**

这句话把 GeneTind 的重点从“卖什么”转向“客户最终获得什么”。它可对应软件、算力和服务，但不会把品牌限制在任何一类硬件或模型上。英文可使用：

> **Turn omics data into reasoning you can reproduce and act on.**

辅助文案不再泛泛写“以 AI 为核心，融合多组学、生物计算与智能分析”，而需要说明逻辑链条：**数据接入与治理 → 计算与工作流编排 → AI 辅助推理 → 可审阅的研究交付**。这条链应成为首页、产品页、销售材料和演示环境的共同骨架。

### 2.2 命名与产品架构

应让用户一眼理解“GeneTind 是什么，GneroAI 是什么，HPC 在其中做什么”。建议采用如下产品架构，并在导航、页面标题和页面内标签中一致使用。

| 层级       | 推荐名称与角色                                       | 面向用户                         | 页面表达方式                                     |
| ---------- | ---------------------------------------------------- | -------------------------------- | ------------------------------------------------ |
| 母品牌     | **GeneTind**：生命科学智能数据与计算基础设施         | 所有用户                         | 讲清“从数据到洞见”的整体能力与行业立场           |
| 智能平台   | **GneroAI**：多组学研究智能工作台                    | PI、研究员、生信团队、数据团队   | 展示对话、任务编排、结果审阅与知识沉淀的研究体验 |
| 计算底座   | **GeneTind Compute**：HPC 与数据基础设施             | IT、平台工程、采购与实验室负责人 | 展示算力、存储、网络、调度、安全及私有化部署     |
| 可扩展能力 | **Gnero Skills / Workflows**：可复现的领域技能与流程 | 生信开发者、平台管理员           | 展示版本、输入输出、依赖、验证状态与复现方法     |
| 专业服务   | **Research Enablement**：迁移、部署、流程验证、共建  | 企业和机构决策者                 | 用项目交付方法、治理边界和真实案例来呈现         |

“GneSkills”“GeneTind-Life-Skills”“GTC-Skills”等名称在公开页面中不宜同时并行。建议选定一个产品名并保留其余名称作为代码仓库或迁移期别名。命名统一本身就是高价值的界面改造。

### 2.3 设计气质

目标气质不应是“赛博生物”或“DNA 霓虹特效”，而应是 **科研级精确、计算级清晰、发现瞬间的温度**。可以将整体风格概括为：

| 维度   | 推荐取向                                 | 应避免的取向                           |
| ------ | ---------------------------------------- | -------------------------------------- |
| 科学感 | 数据结构、样本关系、序列节律、可追溯性   | 装饰性的双螺旋、漂浮分子球、无意义粒子 |
| AI 感  | 推理路径、任务状态、模型协作、可审阅界面 | 泛用机器人头像、紫色脑图、机械人形象   |
| 企业感 | 留白、强信息层级、真实指标、克制动效     | 到处发光、过度玻璃拟态、连环渐变       |
| 生命感 | 柔和的有机曲线、微妙层次、真实研究影像   | 医疗行业常见的蓝色听诊器图库           |

## 3. 视觉系统建议

### 3.1 色彩：建立“数据墨色 + 组学荧光”的有限系统

现有蓝紫色可以保留为辅助色，但不应继续担当整站唯一性格。推荐使用沉稳的近黑蓝作为数据背景，柔和的石灰绿作为“可解释的发现”色，青蓝用于计算与连接，暖珊瑚仅用于高风险、异常或重要标记。绿色不是装饰，而是“发现、验证通过、工作流完成”的语义色。

| Token           | 推荐色值  | 用途                           | 使用边界                         |
| --------------- | --------- | ------------------------------ | -------------------------------- |
| `ink-950`       | `#07131A` | 深色页面主背景、沉浸式产品体验 | 不要纯黑铺满全站                 |
| `ink-800`       | `#10252E` | 深色二级表面、导航悬浮层       | 以轻微明度差建立层次             |
| `paper-50`      | `#F5F4EF` | 浅色内容页、案例页、长文阅读   | 与深色页交替使用，给眼睛留出呼吸 |
| `gene-lime`     | `#CBEF5A` | 发现、完成、主 CTA、重点数据   | 单页面积宜少，不要用作大面积背景 |
| `signal-cyan`   | `#79D8E8` | 数据连接、网络、交互高亮       | 用于 Compute 和流程关系          |
| `variant-coral` | `#FF9B86` | 风险、异常、重要变异或警示     | 必须有语义，不用作普通装饰       |
| `violet-legacy` | `#7D6BFF` | 少量 AI 推理层强调             | 不再作为满屏光晕主色             |

建议取消每一屏固定的“蓝紫网格”。网格只在 **Compute、Workflow、数据表格、产品演示** 中出现，因为它们能说明坐标、计算或数据关系。首页的品牌区则可以采用低对比“序列带”或“样本到洞见”的流动路径，而不是泛用空间感背景。

### 3.2 字体：将“品牌标题”“科研正文”“数据读数”分工

中文建议采用 **思源黑体 / Noto Sans SC** 或兼顾中英文的现代无衬线字体作为正文。英文和产品界面可选 Inter、IBM Plex Sans 或 Geist。数据编号、基因符号、坐标与参数使用 IBM Plex Mono 或 JetBrains Mono。标题不需要刻意追求夸张未来感，而应通过字重、字距和中英文比例建立精密感。

| 文本层级   | 中文建议          | 英文建议              | 风格规则                                               |
| ---------- | ----------------- | --------------------- | ------------------------------------------------------ |
| 品牌主张   | 思源黑体 Heavy    | Inter / Geist 600-700 | 48-72px；限制为 2-3 行；不要中英同权并排堆满首屏       |
| 页面标题   | 思源黑体 Semibold | Inter 600             | 36-52px；保留大量上下留白                              |
| 正文说明   | 思源黑体 Regular  | Inter 400             | 16-18px；行高 1.65-1.8；宽度 34-42 个中文字符          |
| 数据与标签 | IBM Plex Mono     | IBM Plex Mono         | 用于样本数、版本、状态、流程节点和规格，不用于所有正文 |

### 3.3 图形语言：以“科学信息图”替换“模板装饰图”

建议建立三类可复用、但有明确语义的图形资产。第一类是 **Omics Ribbon**：由碱基序列和层级细线构成的柔性带状体，可随滚动产生极微弱的深度变化，用于体现数据流而非 DNA 图标。第二类是 **Research Graph**：将样本、实验、流程、模型与结果连接为节点网络，可在产品页作为真实工作流的可视化载体。第三类是 **Evidence Card**：类似实验记录或数据快照的轻量卡片，包含样本、版本、置信度、可复现状态等真实字段。

人物、实验室、病理切片、测序仪或集群机柜影像都应优先选用真实项目图、授权图或原创艺术化渲染，作为长页面节奏中的锚点。图像不需要逐节出现，但每一个大模块至少应有一个能证明“这是生命科学，不是泛 AI”的视觉证据。

## 4. 首页应如何重写

首页应从“产品和能力全集”变成“一个研究团队如何使用 GeneTind”的短叙事。最有效的首屏不是居中标题加两个按钮，而是 **左侧明确主张，右侧可读的研究智能工作台画面**。右侧视觉可以是可控的前端可视化，不一定要是真实 SaaS 截图，但应包含样本、工作流、模型、结果和审阅状态等结构化信息。

### 4.1 推荐信息架构

| 顺序 | 模块               | 用户要在 5 秒内理解的内容                         | 推荐版式与 CTA                                                          |
| ---- | ------------------ | ------------------------------------------------- | ----------------------------------------------------------------------- |
| 1    | 首屏：从样本到洞见 | GeneTind 用 AI 和计算让组学研究更可复现、更可行动 | 左文右图；主 CTA“预约方案评估”；次 CTA“查看研究工作流”                  |
| 2    | 研究链路           | 数据不是孤立文件，AI 也不是黑箱                   | 横向四段流程：Ingest、Compute、Reason、Review；每段只给一个可见证据     |
| 3    | 三种客户入口       | 我属于哪一种团队，下一步要看什么                  | 非对称三栏：研究团队、平台与 IT、产品与转化团队；每栏进入不同解决方案页 |
| 4    | GneroAI 产品体验   | AI 如何辅助生信任务而非只做聊天                   | 一个大屏工作台，加三条可切换任务流程，而不是三张等宽卡片                |
| 5    | Compute 基础设施   | 为什么能处理敏感、庞大、复杂的数据                | 深色横向结构图：计算、存储、网络、安全；只展示可验证指标与部署模式      |
| 6    | 可复现与安全       | 结果如何被审阅、记录和交付                        | 证据链式版面：版本、输入、流程、输出、审阅；搭配合规与部署边界          |
| 7    | 真实案例或研究场景 | 谁已从中获益，具体解决了什么                      | 1 个长案例优先于 3 个泛化评价；没有真实案例时用“典型工作流”并明确标注   |
| 8    | 最终转化           | 选择下一步路径                                    | 两种 CTA：方案评估和技术交流；文档与 GitHub 放为低优先级链接            |

### 4.2 首屏文案示例

**眉题：** `GENETIND / OMICS INTELLIGENCE INFRASTRUCTURE`

**主标题：** 让组学数据成为可推理、可复现、可行动的研究能力。

**辅助正文：** 从数据接入与高性能计算，到智能工作流与结果审阅，GeneTind 为科研与产业团队建立可落地的生命科学智能基础设施。

**主按钮：** 预约方案评估  
**次按钮：** 查看研究工作流

**右侧视觉内字段示例：**

```text
COHORT  /  1,284 samples
WORKFLOW  /  RNA-seq differential expression
MODEL ASSIST  /  Literature-aware interpretation
REVIEW STATUS  /  18 findings ready for validation
```

如此处理的好处是，用户不必先理解“GneroAI”“HPC”“Skills”等产品名，也可以先理解品牌的工作成果。产品名会在后续模块自然出现。

### 4.3 首页首屏的构图方向

建议采用 **60/40 非对称分栏**。左侧不是严格垂直居中，而是略偏下，以形成向下滚动的势能。右侧的研究智能工作台可以越过页面右侧边界，带来更强的产品感。背景只放一条低对比的 Omics Ribbon，从左下进入，穿过右侧工作台，再延伸到下一段“研究链路”。它形成叙事连接，不是随机的光效。

对于移动端，首屏应先显示核心主张和一个纵向裁切的“研究状态卡”，不要把桌面工作台缩成不可读缩略图。卡片可只呈现“样本数、当前任务、复现状态”三个字段，让用户仍然抓住核心。

## 5. 核心页面的改造方法

### 5.1 GneroAI：从“三张能力卡”到“研究工作台体验”

GneroAI 需要回答的不是“我们有 Chat、Agent、Skills”，而是“研究人员如何用它完成一项可审阅的任务”。建议使用一个默认主流程，例如：**单细胞数据质控 → 聚类注释 → 文献证据辅助解释 → 报告审阅与导出**。页面应展示输入是什么、AI 在哪一步介入、人如何审阅、结果如何保留版本。

| 区块     | 现有表达问题                   | 新表达方式                                                               |
| -------- | ------------------------------ | ------------------------------------------------------------------------ |
| Hero     | 说明性标题与两个外链 CTA       | 写清一个研究成果，并给出产品演示、技术交流两条明确路径                   |
| 产品核心 | Chat、Agent、Skills 并列平铺   | 一个可切换的工作台主画面，Chat、Agent、Skills 作为它的能力层而非独立卡片 |
| 可信性   | 没有输入、输出与人类审阅的证据 | 展示任务轨迹、引用来源、流程版本、人工确认点与导出记录                   |
| 场景     | 泛化的“智能分析体验”           | 用 3 个经过核验的研究场景，明确数据类型、工作量、交付物和边界            |
| CTA      | “进入文档”“探索更多功能”较泛   | “申请试用环境”“获取场景方案”“查看接口与部署文档”按决策阶段分层           |

产品视觉不应保持整页蓝黑网格。建议首屏和产品演示区使用深色“沉浸模式”，随后切到浅色的“研究证据模式”，让流程、引用和解释性内容获得更高可读性。深浅交替也能防止用户在长页中出现视觉疲劳。

### 5.2 HPC：从“规格目录”到“研究计算架构”

HPC 页可以保留详细型号和参数，但它们不该承担页面前半段的主要叙事。第一屏后先展示 **为何生命科学计算不同**：数据吞吐、流程依赖、GPU 任务、敏感数据隔离和可复现计算。接着用一张可视化架构解释 Compute、Storage、Network、Security、Workflow 的协同关系，最后才开放产品筛选与规格对比。

建议将硬件产品区改为“按研究负载选择”而非“按设备类型浏览”。例如：

| 研究负载         | 推荐组合                             | 用户看到的价值                         |
| ---------------- | ------------------------------------ | -------------------------------------- |
| 大队列 WGS/WES   | 高密 CPU + 并行存储 + Workflow 调度  | 缩短批处理周期，稳定处理高并发文件读写 |
| 单细胞与空间组学 | GPU 节点 + NVMe 缓存 + 可视化工作站  | 在交互式分析和批量计算之间平衡         |
| 多模态模型训练   | GPU 集群 + 低时延网络 + 检查点存储   | 提升分布式训练效率与任务可恢复性       |
| 临床或敏感数据   | 私有化部署 + 零信任隔离 + 审计与归档 | 让数据边界、访问权限和交付过程可追溯   |

涉及具体硬件型号、性能倍数、合规资质、代理授权或客户案例时，必须让页面数据与销售、交付、法律和供应商的已核验材料一一对应。无法公开验证的项目可从页面移除或改为“可选配置”“支持评估”的描述。对专业购买者来说，可证实性比更夸张的数字更有说服力。

### 5.3 关于我们与资源：建立“研究者信任”

“关于我们”不要写成普通公司介绍。建议将其变成“为什么 GeneTind 适合研究数据”的信任页：团队背景、数据治理理念、服务范围、交付方式、合作边界和联系入口。博客、技能库、课程等资源不要和商业产品抢首屏导航，而应归入“Resources / 资源中心”，并通过内容类型分类：研究指南、工作流、技术文档、开源项目、活动与培训。

## 6. 组件与交互准则

taste-skill 倡导减少模板化页面感。对 GeneTind 而言，最重要的应用不是使用更夸张的动画，而是确保每个模块都选择适合其内容的结构。也就是说，产品对比可以用表格或架构图，研究流程可以用阶段轨迹，案例可以用长篇叙事，数据状态可以用证据卡。**不要再用一套“三列同高卡片”解释所有事。** [3]

| 组件     | 建议做法                                                                        | 不建议做法                                     |
| -------- | ------------------------------------------------------------------------------- | ---------------------------------------------- |
| 导航     | 控制一级项目在 5-6 个以内；“平台”和“解决方案”用清晰下拉；右侧保留一个高意图 CTA | 在一级导航并列产品、课程、博客、支持和外部站点 |
| 卡片     | 只用于可比较、可筛选或可操作的对象；一组中允许大小和信息密度不同                | 每个模块都用同尺寸圆角卡片，靠渐变和阴影区分   |
| 数据展示 | 采用单宽字体、明确单位、来源、版本或更新时间                                    | 把夸张数字做成无语境的大号装饰                 |
| 图标     | 使用统一线宽的实验、计算、数据流、审阅图标                                      | 依赖彩色 Emoji、泛用火箭、魔法棒或机器人图标   |
| 分隔     | 用留白、背景切换和少量细线建立节奏                                              | 每段都加描边、点阵、渐变条或标签               |
| 图片     | 用真实实验室、平台截图、数据视觉化或授权案例图                                  | 以不相关的科技图库填充区块                     |
| CTA      | 每个视口只保留一个主动作，次动作使用文本链接或浅样式按钮                        | 让“试用、文档、GitHub、预约、了解更多”同等抢眼 |

### 动效原则

动效应服务于“理解”和“反馈”。首屏的 Omics Ribbon 可以在首入场时缓慢完成一次流动；研究流程在滚动到对应位置时依次点亮；产品工作台允许用户切换任务时改变结果面板。除此以外不应持续增加不承载语义的漂浮、粒子、闪烁和跑马灯。对于 `prefers-reduced-motion` 用户，需要提供静态路径和即时切换结果。网页动效不应降低科研场景的阅读效率。

## 7. 内容与可信度治理

生命科学与企业基础设施的购买决策比普通消费型 SaaS 更依赖可验证信息。界面改造需要同步完成内容治理，否则视觉做得越精致，未经验证的数字和泛化案例越会显得突兀。

建议上线前为每一项信息建立最小证据表，包括：内容归属人、适用产品版本、证据来源、发布日期、审阅日期与允许公开范围。客户评价仅使用有书面授权的姓名、机构、职位与原话。未公开客户可改为匿名且具体的“应用场景摘要”，同时明确匿名原因。硬件代理、性能参数、合规与安全声明应该连接到可供销售或技术团队出示的材料。

| 内容类别         | 上线规则                       | 页面标签建议                               |
| ---------------- | ------------------------------ | ------------------------------------------ |
| 已交付产品能力   | 有产品负责人、版本与测试依据   | `AVAILABLE`、版本号或“已支持”              |
| 可选专业服务     | 明确依赖项目评估与交付范围     | `CONSULTATIVE` 或“需方案评估”              |
| 路线图与实验能力 | 不夸大为当前功能               | `IN DEVELOPMENT` 或“内测中”                |
| 性能与成本数字   | 标明场景、基线、测试条件和日期 | “在指定环境下的测试结果”                   |
| 合规与安全       | 不使用模糊的“符合全部标准”     | 指出部署方式、访问控制、审计或认证实际范围 |

## 8. 对现有 Next.js 项目的落地建议

目前项目已经以 Next.js、Tailwind 和组件化结构组织，并分别存在 Hero、Header、GneroAI、HPC、Features、Brands、Testimonials、Pricing 等模块。[1] 改版不应在旧页面上继续叠加样式，而应先抽离设计 token 和内容模型，再重建最关键的页面模板。这样能减少同一背景、同一卡片在各页复制后产生的维护成本。

| 现有位置                                           | 建议动作                                                               | 目标                                   |
| -------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------- |
| `src/styles/index.css`                             | 定义颜色、排版、间距、圆角、阴影、动效 token；删除无语义的全局装饰规则 | 从零散色值与视觉特效转向可治理设计系统 |
| `src/components/Header`                            | 重构导航分类、移动端展开逻辑与唯一主 CTA                               | 降低首页入口认知负荷                   |
| `src/components/Hero`                              | 重做为非对称分栏和结构化研究工作台视觉                                 | 让首屏直接表达 AI + Gene 的交集        |
| `src/components/GneroAI`                           | 将并列能力卡重构为场景驱动的产品体验                                   | 强化可操作性与可信度                   |
| `src/components/HPC`                               | 建立“负载场景 → 架构 → 产品与规格”结构                                 | 让技术信息支持决策而不是淹没决策       |
| `src/components/Brands`、`Testimonials`、`Pricing` | 暂时移出首页，或仅在材料齐全后以真实证据重做                           | 移除启动模板残留与未经证实的社交证明   |
| `src/content/`（建议新增）                         | 以 JSON/MDX 管理案例、产品、指标、工作流、资源                         | 使多语言、审阅和内容更新可控           |
| `src/components/visuals/`（建议新增）              | 集中管理 Omics Ribbon、Research Graph、Evidence Card                   | 形成可复用且带领域语义的视觉资产       |

推荐使用 CSS 和 SVG 完成主要数据路径与信息图，必要时再采用轻量 Canvas。除非视觉化确实承载研究数据或演示价值，否则不建议为首页引入重型 3D 引擎。首屏加载速度、文字可读性和移动端稳定性优先于炫技。

## 9. 建议的实施顺序

下面的顺序以“先聚焦、再重构、后打磨”为原则。它遵循参考项目所强调的审计优先逻辑，但针对 GeneTind 的科研和企业场景进行了定制。[3]

| 优先级 | 工作包                 | 主要产出                                                                   | 完成判定                                                       |
| ------ | ---------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| P0     | 品牌与内容清理         | 品牌一句话、产品命名图、导航重组、CTA 规则、真实性审阅清单                 | 首页不再承载无关入口；每一个对外声明有负责人和证据状态         |
| P1     | 设计系统               | 色彩 token、字阶、间距、表面层级、按钮、标签、数据组件规范                 | 任意页面不再依赖临时色值和通用渐变来表达层级                   |
| P2     | 首页重构               | 新首屏、研究链路、三类用户入口、GneroAI 体验、Compute 架构、可信度与转化区 | 用户在首屏后能说清 GeneTind 解决什么问题、服务谁、下一步做什么 |
| P3     | GneroAI 与 HPC 模板    | 研究工作台产品页、研究计算架构页、负载场景页、参数对比模块                 | 两个页面的视觉与内容结构因产品属性不同而显著区分               |
| P4     | 信任与资源页           | 案例、文档、开源、培训、关于我们与联系页                                   | 所有资源有明确受众、内容类型和转化目标                         |
| P5     | 动效、无障碍与质量验证 | 减弱动效模式、键盘导航、对比度检查、移动端测试、性能预算                   | 视觉效果不牺牲阅读、可访问性和稳定性                           |

### 上线前的 10 条检查

| 检查项     | 判断标准                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| 品牌主张   | 首屏是否不用解释产品名也能说明“为谁解决什么问题”                           |
| 信息聚焦   | 首页是否只有一个主要 CTA，且它对应真实商业或研究流程                       |
| 页面区分   | GneroAI 与 Compute 是否在叙事、色彩、组件和交互上有所区别                  |
| 领域视觉   | 每个核心屏是否出现了与样本、工作流、数据、结果或基础设施相关的有效视觉证据 |
| 卡片纪律   | 是否去除了没有比较、筛选或行动价值的装饰性卡片                             |
| 内容真实性 | 性能、案例、资质、客户与合作关系是否可被内部负责人确认                     |
| 双语质量   | 中英文是否各自自然，避免逐字翻译和双语标题过度竞争                         |
| 可访问性   | 深色页文字、按钮、数据标签是否具备足够对比度和键盘可用性                   |
| 移动端     | 首屏核心主张、CTA 和研究状态卡是否在小屏仍清晰可读                         |
| 模板残留   | 是否已经移除通用模板品牌、无效链接、无关“Pro”导流与泛化评价                |

## 10. 最后建议

这次改版最应该避免的是“把现在的深色网格再做得更酷”。真正能让 GeneTind 看起来属于 **AI + Gene** 的，是让用户在几秒内看到：这里处理的是生命科学数据；这里的 AI 能被研究人员审阅；这里的计算、数据、安全与流程能够一起交付。

建议先完成 **P0 到 P2**。这三步会重塑品牌主张、导航、内容优先级、首页首屏和视觉系统，能够最快让外部观感从“模板化科技展示”转向“有研究语境、有产品逻辑、有企业可信度的生命科学智能品牌”。之后再把同一套系统延伸到 GneroAI 与 HPC 页面。这样能在不推翻当前 Next.js 基础的前提下，完成一次真正的品牌级重构，而不是一次表层换肤。
